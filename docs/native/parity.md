# Native parity release checklist

This inventory implements [#65](https://github.com/Vankata03/pitwall/issues/65) under [rewrite map #64](https://github.com/Vankata03/pitwall/issues/64). The inspected source baseline is `1074e8439c1fa0a0436c7180f61bc8afaafcb62a`, dated 2026-11-05. Repository links refer to that baseline; later behavior changes require an inventory update.

Unchecked boxes are release conditions, not claims that native implementation exists. Checked DEC entries record owner approval only; their linked implementation conditions remain unchecked. Keep IDs stable. Close a **port** item with an implementation reference and named native tests covering its conditions, defaults and failures. Close a **dropped by ADR 000N** item with that ADR and removal/replacement evidence. A **needs owner decision** item blocks closure until resolved; removing behavior requires an accepted ADR. All clauses of an item must pass. Passing web tests alone does not close native parity.

Implementation and assertions establish current behavior; the spec helps locate omissions. Native replacements are identified explicitly. Removing transport does not remove the underlying local action. Source/spec disagreements below do not authorize silent changes.

**Accepted tile baseline:** this tree registers **19 tile types**. The registry glob imports one default module from each non-test `types/*.tsx`; there are 19 files and no second registry. Spec section 11 also has 19 entries. The owner accepted correcting the earlier count of 27 in issue #65 and ADR 0004 on 2026-11-05. All 19 types are inventoried below; see DEC-01.

## Ingest and session model

- [ ] **ING-01 — port.** Select parser per datagram format, accept 2025/2026 into 24 car slots with wider IDs. Unsupported formats report format/parse errors but do not enter model or recording. Source: [parser](../../crates/core/src/telemetry/mod.rs), [Ingest::ingest](../../crates/core/src/ingest.rs).
- [ ] **ING-02 — port.** UID 0 contributes connection/format counters only. Session identity is `(UID, format)`; a new nonzero identity closes the prior identity and resets ordering. Closed identities stay closed for this process run and late packets increment a counter without reopening state. Source: [Ingest::classify](../../crates/core/src/ingest.rs).
- [ ] **ING-03 — port.** Reject non-newer overall frame identifiers per packet type; apply events in arrival order. Final Classification bypasses ordering and closes identity. After SEND allow Session History/classification, ignore other ended input; do not exempt every frame-zero packet. Source: [Ingest::classify](../../crates/core/src/ingest.rs).
- [ ] **ING-04 — port.** Raw recording tap precedes model filters, retaining eligible duplicates/late frames. Measure rate as the maximum preceding-second count among packet IDs 0/2/6/7/13/16, including duplicates, not their sum. Source: [Ingest::ingest/status](../../crates/core/src/ingest.rs).
- [ ] **UDP-01 — port.** Bind all IPv4 interfaces at configured port; receive whole datagrams, cap work per poll and apply incoming model updates without slow UI/filesystem work on the receive path. Advance staleness during silence. Source: [UDP poll](../../crates/core/src/ingest/udp.rs), [runtime worker](../../crates/collector/src/ingest/runtime.rs).
- [ ] **UDP-02 — port.** Forward unchanged live bytes before parsing/filtering, including unsupported/rejected inputs. Off/empty by default; resolve host:port off the receive path, one address per target, deduplicate resolved destinations, support IPv4/IPv6. Replay never forwards. Source: [Forwarding::prepare/send, LiveUdp::poll](../../crates/core/src/ingest/udp.rs).
- [ ] **UDP-03 — port.** Count forwarding failures without retries delaying ingest. Prepare port/target updates before swapping; failure retains previous listener/forwarding, and target-only changes preserve queued input. Source: [PreparedUpdate](../../crates/core/src/ingest/udp.rs).
- [ ] **MODEL-01 — port.** Explicit arrival-time apply/advance drives waiting/live/ended/lost. After 30 seconds silent while live, retain values stale with paused-or-closed wording; same UID can resume. Retain classification/session until new identity resets it; weekend sessions share no history. Source: [SessionModel](../../crates/core/src/model/mod.rs), [spec §5](../spec/v1.md).
- [ ] **MODEL-02 — port.** Keep live model running while a separate replay model is selected. Returning from replay immediately exposes current live state. Source: [runtime](../../crates/collector/src/ingest/runtime.rs), [replay selection](../../crates/collector/src/replay/routes.rs).
- [ ] **MODEL-03 — port.** Keep whole-session laps, sectors, stints, stops and penalties for every valid car before focus changes. Result statuses 0/1 are invalid slots. Retired cars remain frozen with reason; AI takeover keeps identity. Spectating makes spectator index the player; secondary player has no special handling. Source: [SessionModel/CarView](../../crates/core/src/model/mod.rs).
- [ ] **MODEL-04 — port.** Regulations are per car: 2025 format is pre-2026, otherwise use telemetry regulations field. My Team comes from `my_team`, not an empty-slot team ID. Source: [CarView::regulations/is_my_team](../../crates/core/src/model/mod.rs).
- [ ] **MODEL-05 — port.** Restrict fuel, ERS, front brake bias, damage/wear and tyre sets; discard formerly public values when restriction starts. Unknown permission cannot become zero. Keep temperatures, pressures, compound/age, timing/positions and aero independently available. Source: [Car::permission](../../crates/core/src/model/mod.rs), [status split](../../crates/core/src/model/status.rs).
- [ ] **MODEL-06 — port.** Per-group readouts stale after three expected intervals measured on arrival time; all available groups stale while lost. Preserve restricted/absent without payload. Player pit window remains absent for other cars; latest forecast is separate from weather-change history. Source: [Group::read and SessionModel](../../crates/core/src/model/mod.rs).
- [ ] **FACT-01 — port.** ERS percentage uses 4 MJ capacity, still assumed; condition is 100 minus raw wear with source state; fuel delta is received remaining laps unchanged. Source: [CarView facts](../../crates/core/src/model/facts.rs).
- [ ] **FACT-02 — port.** Race/sprint gaps combine game minute/millisecond fields; whole laps behind floor race-distance difference/track length. Timed gaps use valid session-best lap; no lap is absent. Source: [CarView::gaps](../../crates/core/src/model/facts.rs).
- [ ] **HIST-01 — port.** Live lap/sector completion accepts later authoritative Session History corrections to validity, times, bests and stints, updating stable IDs rather than duplicating entries. Source: [history](../../crates/core/src/model/history.rs), [store corrections tests](../../dashboard/src/runtime/stores.test.ts).
- [ ] **HIST-02 — port.** Fitted tyre changes, not every pit visit, delimit stints; retain used starting age. Drive-through, stop-go and wing-only visits remain separate stops with lap, lane/stopped durations and in-progress state. Source: [history](../../crates/core/src/model/history.rs).
- [ ] **REW-01 — port.** Explicit flashback or newer-frame periodic-group time reversal rewinds future facts; ordinary events and lagging packet groups cannot trigger false rewinds. Rewind laps/sectors/stints/stops/penalties/samples, validity, retirement and future group values. Source: [rewind_for](../../crates/core/src/model/rewind.rs).
- [ ] **REW-02 — port.** Bump epoch, recompute bests, retain abandoned log entries marked rewound, append one game/derived flashback entry. Late Session History/classification do not rewind. Keep permissions conservative pending new participants. Source: [rewind](../../crates/core/src/model/rewind.rs).
- [ ] **LOG-01 — port.** Collect game events plus derived flags, marshal/safety state, pit entry/exit and weather in one ordered session log. Tile filtering cannot discard collected history. Outstanding penalty seconds/warnings/DT/SG come from authoritative Lap Data separately from penalty events. Source: [race_control](../../crates/core/src/model/race_control.rs).
- [ ] **REF-01 — port.** Best is this car's fastest valid lap; previous is its last completed lap, even invalid. Invalid laps keep delta but cannot become best; no session-fastest fallback. Source: [delta](../../crates/core/src/model/delta.rs).
- [ ] **REF-02 — port.** Use 5 m buckets, linear interpolation, no delta smoothing or negative-distance samples, no bridging gaps over 100 m. Keep pit/in/out-lap data with valid distances. Named references without samples give no live delta; summary comparisons may still work. Source: [LapTrace/DeltaState](../../crates/core/src/model/delta.rs).
- [ ] **REF-03 — port.** At finish use official times against the reference existing before that finish; S3 is lap minus S1/S2. Retain bounded current/recent/best/former-best traces and immutable completed samples, plus full summaries. Deep rewinds can leave delta absent until new samples form. Source: [delta](../../crates/core/src/model/delta.rs).
- [ ] **REF-04 — port.** Time Trial personal best/rival are player-only summary references in Time Trial; never seed samples or session best from them. Source: [time_trial_reference](../../crates/core/src/model/delta.rs).

### Several windows and the stream window evidence (#75)

`pitwall_core::window_set` keeps the app's windows in `windows.json` under the data
folder. Each dashboard window has its own id (`main`, then `dashboard-2`, ...), so its own
choices file (`windows/<id>.json`); stream windows are `stream-1`, `stream-2`, .... A
closed window keeps its entry and the next window of its kind reuses it. Windows open at
quit (or at a crash) come back on the next start; `place` returns each to its monitor
and position, moves it back onto a shrunken monitor, and centres it on the primary
monitor when its monitor is gone. A stream window is opened from a dashboard's Display
menu for that window's layout and units, with a solid, green-key (`#00FF00`) or
magenta-key (`#FF00FF`) background. It has no title bar, chrome, banners or footer,
draws every tile (the Notice tile included) with rows fitted to the window height
(`GridGeometry::stream`), follows the player car (tile pins still apply), moves by dragging anywhere and closes with
Escape or the system menu. A missing, deleted or renamed layout leaves only the
background, is reported to status and the log once per change
(`Command::WindowProblem`), and recovers when the layout exists again.

| --- | --- |
| WIN-01 | `crates/core/tests/window_set.rs` (ids, reuse, restore, quit, `.bad`, monitor-safe placement), `window.rs` (`windows_over_one_library_keep_their_own_choices_and_see_each_others_saves`) |
| EDIT-04 | `window.rs` (saves reach other windows; an editor keeps its draft with a conflict notice and its Done replaces the whole layout; delete or rename moves viewers to Pitwall Classic), `layout_controller.rs` |

A manual check on 2026-11-06 ran the debug build with an isolated data folder on a
machine with two 2560x1440 monitors. Two dashboard windows (the second from a second
launch) were moved with `SetWindowPos`, one to each monitor; after the process was killed
and restarted, both came back at the same rectangles on the same monitors. Seeded stream
windows restored too: `pitwall stream: Pitwall Classic` at its saved place with a green
background and no title bar, and a stream window for a missing layout, saved on a monitor
that does not exist, opened centred on the primary monitor showing only its magenta
background, with the problem in the log. Its close logged the problem as cleared and
marked it closed; Escape closed the other stream window; an ordinary restart restored only
the two dashboards. Screen captures read the backgrounds at the same values as a GDI
window filled with `#00FF00` on this display.
